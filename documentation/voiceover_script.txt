AI RECRUITMENT AGENT — DEMO VOICEOVER

INTRO
This is my AI Recruitment Agent prototype for Technical Pots IT Solutions. The goal is to automate the recruitment workflow while keeping candidate evaluation explainable and under recruiter control.

1. REQUIREMENT
The recruiter enters the role, number of openings, experience range, required skills, and target applications. For this demo I am using a Mobile Developer role with two openings, a two-to-four-year experience target, and Flutter, Kotlin, REST APIs and Firebase as required skills.

2. JOB DESCRIPTION
The agent converts the hiring requirement into a structured job description. The generated JD contains the role summary, responsibilities, required skills, qualifications, preferred skills, and culture and benefits. The recruiter reviews the JD before moving forward.

3. RESUME SOURCING
For this prototype, the candidate pool is six synthetic resumes stored locally. Each resume carries simulated source metadata such as Naukri, LinkedIn or Indeed. I am not claiming live scraping from those platforms. In production, this source adapter would connect to approved ATS or job-board integrations.

4. RESUME PROCESSING
The system processes each resume and extracts structured information including experience, skills, education, previous roles and project evidence. This converts unstructured resume content into data that the matching engine can evaluate consistently.

5. MATCHING
Next, every processed resume is compared against the approved JD. The UI shows each required skill as matched or missing, compares experience with the requested range, and displays relevant candidate evidence.

6. SCORING
The important part is that the final numerical score is deterministic. The model is fifty points for mandatory skills, twenty for experience fit, ten for preferred skills, ten for role relevance, and ten for relevant evidence. The LLM can help with language understanding, but it does not arbitrarily choose the final score.

7. RANKING
The application calculates the score for every candidate and ranks them using the same rules. The UI shows the complete ranking, each candidate's score breakdown, and the arithmetic behind the score.

8. WHY NUMBER ONE
For the top-ranked candidate, the system generates an explanation from the same score breakdown. I can therefore show exactly which skills matched, how experience was handled, which preferred skills matched, and why the candidate ranked above the next candidate.

9. RECRUITER CONTROL
The recruiter then confirms the shortlist. The system does not make an irreversible hiring decision automatically.

10. INTERVIEW PREPARATION
Finally, the system prepares interview slots and invitation drafts for the shortlisted candidates. In this prototype they are drafts for recruiter review; no external calendar meeting is actually booked and no email is sent.

CLOSING
The key architecture is simple: the LLM handles unstructured language understanding, while the application controls structured business logic, scoring and ranking. This makes the recruitment workflow easier to inspect, reproduce and extend.
